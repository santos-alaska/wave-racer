# INK TIDE — architecture contract

Read this before touching any subsystem. It is the agreement that lets seven
subsystems be built in parallel without merge conflicts or integration surprises.

## Hard rules

1. **Zero external assets.** No fetched models, textures, HDRIs, fonts or audio
   files. Geometry is built with `BufferGeometry`, textures come from
   `src/render/textures.ts` (canvas 2D / procedural), audio is synthesised with
   Web Audio. If it isn't generated by our own code, it does not ship.
2. **No PBR.** No `MeshStandardMaterial`, `MeshPhysicalMaterial`, environment
   maps, IBL, or real-time shadow maps with soft penumbra. Every solid surface
   goes through `createCelMaterial()`. If a surface reads as physically based,
   it is a bug.
3. **One palette.** Never write a colour literal in a subsystem. Add tones to
   `src/core/palette.ts` and reference `PAL.*` / `HEX.*`.
4. **One wave field.** Never re-derive wave height. CPU code calls
   `sampleOcean()` / `sampleHeight()`; GPU code includes `GERSTNER_GLSL` and is
   fed `uWaveA` / `uWaveB`. Both live in `src/water/gerstner.ts`.
5. **File ownership is exclusive.** Only edit files your subsystem owns (table
   below). Need something from another subsystem? It goes through the interface
   in `src/core/types.ts`. If the interface is missing something, say so in your
   report rather than reaching across.
6. **No allocation in the frame loop.** Preallocate `Vector3`/`Quaternion`
   scratch objects at module scope. This game must hold 60 fps at retina.
7. **Frame-rate independence.** Use `damp()` / `dampAngle()` from
   `src/core/mathx.ts`, never a bare `lerp(a, b, 0.1)` against a variable dt.

## Coordinate system

- Y is up. The ocean's rest plane is `y = 0`.
- A boat with `heading = 0` faces **+Z**. Heading increases turning toward +X.
- One world unit is one metre. A boat is ~4.6 m long and tops out near 29 m/s.

## The cel pipeline — how to make a surface

```ts
import { createCelMaterial, applyCel } from '../render/celMaterial';

const set = createCelMaterial({
  color: PAL.hull0,
  outlineWidthPx: 2.6,   // constant screen-space width
  rimStrength: 0.7,
  specSize: 0.86,
  chunks: { /* optional vertex/fragment injection */ },
});
applyCel(mesh, set);     // assigns material, registers prepass, adds outline child
```

`createCelMaterial` returns **three** materials built from the same vertex
chunks:

- `main` — the shaded surface
- `prepass` — GLSL3, writes the MRT G-buffer (view normal + linear depth +
  object id) consumed by the Sobel edge pass
- `outline` — inverted hull, `BackSide`, pushed along `aSmoothNormal` by a
  **constant number of screen pixels**

If your surface displaces in the vertex shader (ocean, wake ribbons, rider
limbs), put that displacement in `chunks.vertexBody`. All three materials share
it, so the outline and the G-buffer stay in register. Writing a bespoke outline
shader is the fastest way to get outlines that float off the model.

**Two line systems, tuned not to double up.** The inverted hull owns exterior
silhouettes. The Sobel post pass owns interior lines the hull cannot produce.
Outline meshes set `userData.skipPrepass = true` so they never enter the
G-buffer — otherwise both systems ink the same silhouette and you get a
doubled, muddy edge.

Set `edgeBias: 0` on a material to exclude it from the screen-space pass
entirely (the sky and the water use this).

## The frame loop

`src/main.ts` builds a `GameContext` and drives registered `Subsystem`s in
`order`. Lower runs first:

```
 10  input
 20  ocean          (advance wave time, recentre grid)
 30  boat physics   (samples ocean)
 40  ai drivers     (writes controls consumed next frame)
 50  race state     (checkpoints, laps, standings)
 60  riders         (pose from boat state)
 70  fx             (wake, foam, spray)
 80  camera
 90  audio
100  hud
```

Register with `game.add(subsystem)`. Never call another subsystem's `update()`.

## Harness API

`src/main.ts` exposes `window.__INKTIDE__` when loaded with `?harness=1`:

| Member | Purpose |
|---|---|
| `ready: boolean` | Set true once the first frame has rendered |
| `reset()` | Restart the race deterministically |
| `setPhase(phase)` | Force `'countdown' \| 'racing' \| 'results'` |
| `setControls({steer, throttle, brake, drift, autopilot})` | Script the player |
| `simulate(seconds, dt)` | Advance with a **fixed** step — reproducible |
| `simulateUntil(predSrc, maxT, dt)` | Advance until a predicate over `stats()` holds |
| `settle(frames)` | Render N frames so springs/particles land |
| `release()` | Hand the clock back to real time |
| `setCameraPreset(name)` | See presets below |
| `stats()` | fps, frameMs, triangles, drawCalls, boat state |
| `probe()` | Per-racer numeric dump: heading vs track tangent, lateral error, lap, checkpoint, place |
| `rendererInfo()` | GL vendor/renderer string |

Three properties of the harness are load-bearing and were each learned the hard
way:

1. **The script owns the clock.** `simulate()` sets a `scripted` flag that
   suppresses the rAF step. Without it, the `await`s inside `simulate()` let
   real-dt frames slip in and the "deterministic" harness produced different
   boat state on every run.
2. **The scripted player drives on autopilot.** `steer: 0` at full throttle
   drives the player 1.2 km off the circuit inside a minute, which put a WRONG
   WAY banner in nearly every frame and pushed the AI pack out of shot. Shots
   pass `autopilot: true` so they frame a real racing situation.
3. **Transient states are hunted, not timestamped.** `air`, `land`, `foam_wake`
   and `hud` use `until:` predicates. A fixed timestamp silently stops proving
   anything the moment physics is retuned — which already happened once here.
   The run prints `⚠ STATE NEVER REACHED` when a hunt fails; trust it.

For numeric diagnosis rather than pixels:

```bash
node harness/probe.mjs --port=5310 --at=0,5,20,60
```

This is how "the boats are driving the wrong way" was disproved — all four had
`heading · tangent = 1.00`; the fault was in the harness, not the game.

Camera presets the harness may request: `chase`, `far`, `bow`, `wake`, `rider`,
`orbit_near`, `far_boat`, `broadcast`, `aerial`, `sky`, `auto`.

Capture frames with `node harness/capture.mjs --shots=hero,foam_wake`.
**Every visual claim must be backed by a captured frame, never by reasoning
about what the code should do.**

## Performance contract

Budget at 1440×810 @ dpr 2 on an M-series MacBook, Chrome:

- **≤ 220 draw calls**, **≤ 1.6 M triangles** per frame
- Ocean: one instanced/merged grid per LOD ring, not per tile
- Four boats + riders: instance or merge aggressively; a rider is ~12 parts and
  must not cost 12 draw calls
- Particles: one `Points` or instanced system per FX type, never per emitter
- The adaptive resolution controller in `src/render/renderer.ts` owns pixel
  ratio; do not call `renderer.setPixelRatio()` anywhere else

## Reporting

When you finish, report honestly against the target, not against "it runs".
State a percentage and name what is missing. "Foam is at 70% — the wake ribbon
scrolls and spreads but does not yet dissipate by age" is useful. "Foam
complete" when it is not costs the whole team a review cycle.
